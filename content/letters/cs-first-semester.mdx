如果你刚来大学，听见身边有人讨论 Linux、GitHub、算法竞赛，甚至已经在做项目，而自己还分不清“程序”和“软件”有什么区别，先别慌。入学时大家的起点本来就不一样。有人高中写过代码，有人第一次拥有自己的电脑；后者不是落后，只是需要一张更清楚的地图。

这封信写给那个在机房里偷偷搜索“环境变量是什么”的你。它不卖四年逆袭路线，也不承诺照做就能拿到实习。读完以后，你只需要知道：这学期先抓什么，卡住时怎么继续，哪些事可以暂时不做。

## 一、先弄清楚：计算机专业到底在学什么

把专业想成一栋楼。编程语言是你进门用的工具；数据结构与算法帮你组织问题、衡量成本；计算机组成、操作系统和网络解释程序为什么能跑起来；数据库与软件工程教你把能跑的代码变成能维护的系统。数学给这栋楼提供推理能力，英语让你能直接读文档和报错。你不必在大一把整栋楼建完，但要知道每门课大约放在哪一层。

因此，不要因为一门入门课只讲循环、数组，就断定“计算机不过如此”；也不要看了一个复杂项目，就认定自己必须提前学完所有课程。每周选一个课堂概念，问三个问题：它解决什么问题？一个最小例子是什么？我能不能关掉教程自己重做？第三个问题最诚实。

《上海交通大学生存手册》里让我印象深刻的，不是某条具体选课技巧，而是提醒学生走出被动等待安排的状态。它写给交大学生，学校制度和课程细节不能照搬到安理工；但“主动核实、主动寻找信息”的方法可以借鉴。实际选课、考试和培养要求，始终以你所在学院当年的官方通知为准。

## 二、第一学期别囤工具，先练出一个能工作的环境

刚开始你不需要买一堆付费软件，也不用为了“专业感”立即换系统。先让自己的电脑稳定完成四件事：编辑一个文件，在终端进入它所在的目录，运行课程要求的程序，保存一份能找回的代码。课堂指定 C 就先把 C 跑通；指定 Python 就先把 Python 跑通。一个月换三种语言，通常只会把三份安装教程看得很熟。

很多人第一次卡住，不是因为不会写算法，而是不知道程序究竟从哪里运行。你可以做一个小练习：建一个 `hello` 文件夹，里面放源码和一份记录运行步骤的 `README.md`；从终端进入文件夹，运行它，再故意输错一次命令，读懂报错说的是“文件找不到”、还是“语法不对”。等你能解释这些差别，再慢慢接触编辑器插件、包管理、虚拟环境。

接着学最小限度的 Git：查看改动、提交一次、把仓库推到自己能访问的地方。Git 不是求职装饰，它首先是“我昨天那版代码去哪了”的解药。不要上传密码、密钥、身份证件或带隐私的课程材料。MIT 的 [The Missing Semester](https://missing.csail.mit.edu/) 和 [CS 自学指南的工具章节](https://csdiy.wiki/) 都很适合在课外按需查阅；把它们当工具箱，不是开学一个月必须刷完的课表。

## 三、真正拉开差距的，是你如何处理“不会”

第一道作业题想半小时没有思路，很正常。可怕的是把“不会”直接交给搜索结果：复制一段代码，绿色的通过提示出现了，自己却不知道输入改一点会怎样。下次碰到同类问题，它还会像新题。

试试这套更慢、也更管用的顺序。先用纸写清输入和输出，手算一个最小例子；再把大问题拆成两三个动作；写出最粗糙但能运行的版本；用正常、边界和错误输入各试一次。仍然卡住，就记录你试过什么、实际输出是什么、你原本期望什么，再问同学、老师或 AI。这样提出的问题通常很快能得到有用回答。

例如程序打印 `0`，你期望 `6`。只说“代码怎么错了”信息量很低；说“输入 3 个数，循环应累加到 6，但每轮结果都变回 0，我怀疑变量初始化的位置”，你已经把问题缩小了一半。调试不是天赋，更像侦探工作：找证据，缩小范围，修正假设。用 AI 也一样，请它解释报错或给出测试思路，最后自己关掉答案重新写一遍。关于怎么把 AI 当家教，站内还有一封[专门的来信](/letters/ai-as-tutor)。

## 四、数学、英语和课堂，不是“以后再补”的背景板

高数和线代刚学时可能离写网页很远，但函数、向量、证明与抽象能力会在后面的算法、图形学、机器学习等方向反复出现。没必要因为“未来用不到”而直接放弃，也没必要每一节都追求竞赛级深度。比较稳的做法是跟上本校课程，把不会的定义和例题标出来，每周固定补一次，而不是期末前重新学整本书。

英语同样不只是四六级。你以后会读到英文的错误提示、官方文档、开源项目说明。每天挑一小段与当前作业相关的英文材料，先猜意思，再查词；比背一百个暂时用不到的技术词更容易坚持。遇到机器翻译与原文不一致时，回到原文核对。

课堂也值得认真对待。它给你一个经过安排的起点和可求助的人。觉得进度慢，可以自己加练；觉得跟不上，就利用答疑、助教和同学讨论。网上的“从零到大厂”经验常省略了个人基础、时间和学校环境。知乎、B 站、小红书上的分享可以帮你发现问题，但别把别人的时间线当你的考核表。

还有一件很朴素的事：建立自己的资料秩序。课程群里的文件、老师发的课件、你写的代码和随手拍的板书，最好按“学期—课程—日期或主题”放好。复习时不用在聊天记录里翻半小时。笔记也不用做得像精美手账，只写下课堂没听懂的定义、一道自己做错的题、一个下周要问的问题。笔记的用途是帮未来的你找到断点，不是供人参观。

如果某门课已经听不懂两周，不要等期中考试来宣判。挑最近一次作业里最小的不会点，带着题目去答疑，或者找一个愿意互相讲题的同学。能把“我整门都不会”拆成“这个循环为什么少算一次”，学习就重新有了抓手。寻求帮助不是能力不够，而是你在利用大学提供的反馈渠道。

## 五、项目从身边的问题长出来，不从简历标题长出来

“做项目”听起来很大，其实大一可以很小。比如写一个统计本周学习时间的小程序、把课程资料按文件名整理好、做一个只给自己用的食堂清单网页。关键不在技术名词，而在你能说清楚：谁需要它，输入是什么，输出是什么，遇到什么错误，你改过哪一版。

给自己设一个两周上限。第一周做出能用的最小版本，第二周补上错误处理、说明文档和一两个真实使用场景。做不完就缩小范围，不要无限重写。把过程留下来：截图、版本记录、一次失败和一次修复。它们比“精通十种框架”这样的自我介绍可信。

如果你现在连课堂作业都很吃力，就先别另开一个大项目。把作业做扎实、写清楚运行方法，本身就是起点。等你能独立完成一个小程序，再考虑找同学合作。合作时先约定分工、文件放哪、什么时候合并代码，省下的沟通成本可能比新学一个库还多。

请警惕另一种看起来很勤奋的绕路：看到网上有份“必学清单”，就同时开始算法、前端、机器学习和网络安全。每条路线都只学开头，最后留下几十个收藏夹和很少的作品。选方向可以靠试，不必靠猜。先用两周完成一个小东西，做完以后再问自己：我喜欢的是设计界面、解决逻辑问题、处理数据，还是理解系统怎么运转？兴趣往往在做事之后才变得具体。

如果一份经验帖让你越读越心慌，先停下来问：这件事是本学期课程真正需要的，还是别人的个人选择？它会帮我解决眼前的一个问题吗？不能回答，就先放进“以后再看”，把今天的作业、睡眠和一次真正的休息留在日程里。大学不是一场谁最早把履历填满的比赛。想继续思考大学生活的节奏，可以读读[《让本科生做回本科生》](https://zhuanlan.zhihu.com/p/2086055557534835405)；读任何经验文章时，都请结合自己的处境判断，不必把它变成新的一张待办清单。

## 六、四周起步法：足够小，才能真的开始

**第 1 周：**看一眼培养方案和本学期课表，记下每门课的考核方式与答疑渠道。电脑上只配好课堂必需的语言和编辑器，运行一个最小程序。

**第 2 周：**每次写完作业，用三句话记“题目要什么、我卡在哪、最后怎么解决”。把重复出现的卡点单独列一页；学会用终端找到文件，而不只是反复双击。

**第 3 周：**给一个作业或小练习建 Git 仓库，提交至少两次有意义的修改。找一份相关的官方文档，读懂其中一个示例。遇到问题，带着你的输入、输出和尝试过程去问。

**第 4 周：**回看前三周：哪些课已经掉队，哪些问题总在重复，哪里最需要老师或同伴帮忙？只选一个小问题做两周项目，或者决定暂时不做、先补课程。两种选择都合理。

每天不用把时间塞满。给上课、作业、睡眠、吃饭、运动和朋友留位置。所谓自律，不是把日历染成一整片颜色，而是知道今天最重要的两件事，完成后还能正常生活。

这四周里，你大概还会遇到一些不在课程表上的事：社团招新、班级活动、室友作息、回家的车票。它们不是“学习的干扰项”，本来就是大学生活的一部分。做选择时可以问自己两个问题：这件事是我真想试，还是怕错过才答应？如果这周已经很满，能不能先参加一次体验，而不是立刻承担长期职责？对社团、竞赛、实验室都适用。你不需要在开学第一个月证明自己什么都能兼顾。

如果你发现自己连续几周睡不好、吃不下、上课也很难集中注意力，请先把身体和情绪放在进度表前面。和信任的人聊聊，了解学校的辅导员、心理咨询或校医院有哪些支持。学习计划可以重排，健康没必要拿来交换一份漂亮的履历。

到了月底，不妨做一次只有十五分钟的复盘：挑出一件已经掌握的事、一件仍然不懂的事、一个下月想试的小动作。不要把它写成审判自己的成绩单。比如“现在能看懂编译错误”“数组越界仍常犯”“下周去问一次助教”，这三句就够了。与其追逐别人分享的完美日程，不如让自己的下一步越来越清晰。

## 七、最后，允许自己有一段“不像计算机学生”的时间

你可以暂时不会 Linux，不知道将来做前端、后端还是研究；可以在第一次提交代码时手抖，也可以发现自己其实更喜欢设计、产品或交叉学科。专业不要求你在报到那天就有完整身份。

如果一个学期之后，你能独立运行课程程序，遇到报错不再只会重装软件，知道向谁求助，能说出一门课与另一门课的联系，那么这学期已经很有收获了。先把下一步走清楚，路会在实践里慢慢显出来。
